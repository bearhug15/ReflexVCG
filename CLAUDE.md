# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ReflexVCG generates formal verification conditions (VCs) for programs written in **Reflex**, a small
C-like DSL for programming PLC-style reactive controllers (processes with states, transitions, timeouts).
Given a `.rx` source file, it parses the program, builds an internal program graph, runs a static analysis
pass to prune unreachable/impossible paths, and emits Isabelle/HOL lemmas (one `.thy` file per VC) that a
human later proves in Isabelle to show the program satisfies its requirements. See `FinalVCGRules.pdf` for
the formal rules this implementation follows.

## Build / test / run

Maven project, Java 17. The ANTLR grammar is compiled to a parser via the `antlr4-maven-plugin` during the
`generate-sources` phase — always build through Maven so `ReflexLexer`/`ReflexParser`/`ReflexBaseVisitor` get
generated (they are not checked into `src/`, only the `.g4` source is).

```
mvn compile                      # generates ANTLR sources + compiles
mvn test                         # run all tests
mvn test -Dtest=VCGeneratorTest                       # single test class
mvn test -Dtest=VCGeneratorTest#newTurnstile           # single test method
mvn package                      # builds ReflexVCG.jar (jar-with-dependencies) via maven-assembly-plugin
```

Run the generator:

```
java -jar target/ReflexVCG-1.0-jar-with-dependencies.jar -s path/to/program.rx [-o outDir] [-e simple|regular] [-pe true|false] [-g true|false] [-a true|false]
```

CLI flags (`su.nsk.iae.reflex.Main`):
- `-s` source `.rx` path (required)
- `-o` output dir (defaults to source's folder)
- `-e` expression semantics: `regular` (full C-like, default) or `simple`
- `-pe` split process expressions for attributes; only applies with `-e regular` (default `false`)
- `-g` also export a `.gv` program-graph (Graphviz) alongside the VCs (default `false`)
- `-a` enable static analysis to discard impossible VCs (default `true`)

Tests in `VCGeneratorTest` build small Reflex programs inline (as strings), run the full pipeline, and write
`.thy` output into `src/test/testResult/` — that directory is git-ignored and regenerated by test runs, do
not hand-edit files there.

## Pipeline architecture

There are two generations of most core classes in this codebase (`VCGenerator`/`VCGenerator2`,
`ProgramAnalyzer`/`ProgramAnalyzer2`, `ExpressionVisitor1`/`ExpressionVisitor2`, etc.) — **the code paths
suffixed `2` are the current/live ones**; `Main` and all active tests wire up `VCGenerator2` only. Do not
extend the legacy (unsuffixed) classes; they are effectively dead code kept for reference (see also
`Reflex.g4` vs. the newer `NewReflex.g4`/`Reflex.ebnf` — `Reflex.g4` is the grammar actually compiled by the
Maven ANTLR plugin).

The generation pipeline (driven by `VCGenerator2`, `su.nsk.iae.reflex.vcg`):

1. **Parse** — ANTLR (`Reflex.g4`) produces a `ReflexParser.ProgramContext` AST. (`Main` does this before
   constructing `VCGenerator2`.)
2. **Metadata & mapping** — `VariableMapper` resolves variable names/scoping; `ProgramMetaData` collects
   program-wide info (variable types, input variables, clock, etc.) needed by every later stage.
3. **Graph building** — `GraphBuilder` (`ProgramGraph/GraphRepr`) walks the AST with a `ReflexBaseVisitor`
   and builds a `ProgramGraph` (a jgrapht graph of `IReflexNode`s — one node type per language construct:
   `IfElseNode`, `SwitchNode`, `TimeoutNode`, `SetStateNode`, `ProcessChangeNode`, `ResetNode`, `StateNode`,
   `ProcessNode`, `ProgramNode`, etc., all in `GraphRepr/GraphNodes`). Expressions are lowered by
   `ExpressionVisitor` implementations (`ExpressionVisitor1` = simple semantics, `ExpressionVisitor2` =
   regular/full semantics — selected by the `-e`/`isSimpleExprVisitor` flag) into the `expression` package
   types (`BinaryExpression`, `UnaryExpression`, `CastExpression`, `CheckStateExpression`, ...) and
   `formulas` package (`ConjuctionFormula`, `ImplicationFormula`, `EqualityFormula`, `StateFormula`, ...).
   `GraphBuilder` also records an `ASTGraphProjection` (AST node → graph node) and populates an
   `AttributeCollector` with per-node `IAttributed` attributes (`ProcessAttributes`, `StateAttributes`,
   `ProgramAttributes`) describing control-flow context (branching fragments, process activity/status,
   potential state changes — see the `attributes` package).
4. **Static analysis** — `ProgramAnalyzer2` post-processes the collected attributes (`liftAttributes`,
   `additionalAttributeArrangement`, `grouping`) to determine, e.g., which processes can be active/started in
   which state, used later to prune impossible branches.
5. **Rule checking** — `RuleChecker` (`RuleChecker/IRuleChecker`) decides, during graph traversal, whether an
   `AttributedPath` + candidate next node is a *compatible* (reachable/consistent) continuation; this is how
   `-a` static analysis discards VCs that could never occur.
6. **VC generation / traversal** — `VCGeneratorIterator` performs a DFS-with-backtracking traversal of the
   `ProgramGraph` (`AbstractGraphIterator`), using two traversal listeners: `AttributeTraversal` (maintains
   the current `AttributedPath` and consults `RuleChecker` to prune) and `VCTraversal` (accumulates the
   Isabelle statement strings for the current path via each node's `createStatements`). One VC is finalized
   whenever traversal reaches a node with no outgoing edges.
7. **Printing** — `VCPrinter` writes one `.thy` file per VC plus the base theory files, using
   `IStatementCreator`. `IsabelleCreator` is the concrete (only) implementation, translating expressions,
   formulas and statements into Isabelle/HOL syntax matching the theories in `src/main/resources/ReflexTheory/`
   (`Reflex.thy` defines the `state`/`getVar*`/`setVar*` semantics; `ReflexPatterns.thy` holds reusable proof
   patterns). `IStatementCreator` is an abstraction point if another target language/prover were ever added.

`Main` wires steps 1–7 together; `VCGenerator2`'s constructor runs parsing→graph building→analysis eagerly,
and `generateVC(source, destination)` runs traversal→printing (and optional `.gv` graph export via jgrapht's
`DOTExporter`).

## Key architectural notes

- **Graph nodes carry their own codegen.** Each `IReflexNode` knows how to turn itself into Isabelle
  statement strings (`createStatements(IStatementCreator, int stateCounter)`) and how many "virtual states"
  it introduces (`getStateShift()`); the traversal in `VCGeneratorIterator` is generic over node type.
- **Backtracking traversal, not a simple visitor.** `VCGeneratorIterator` explicitly maintains a
  `branchPoints` stack to explore every path through `if`/`switch`/`timeout` branches (each producing a
  separate VC), pushing/popping accumulated attribute state and VC strings as it backtracks — don't assume a
  single forward pass will visit each node once.
- **Two expression semantics live side by side** (`isSimpleExprVisitor` flag): "simple" vs. "regular"
  C-like expression handling, each with its own `ExpressionVisitor`/`ExprGenRes`/`ExprRes` result types
  (`ExprGenRes1`/`ExprRes` for visitor 1, `ExprGenRes2` for visitor 2). Match the visitor version's
  conventions when touching expression codegen.
- **Isabelle theories are the coupling point with correctness.** Changes to statement/expression codegen in
  `IsabelleCreator` must stay consistent with the semantics defined in
  `src/main/resources/ReflexTheory/Reflex.thy` — a mismatch produces `.thy` files that don't type-check or
  don't prove in Isabelle even though the Java build succeeds.
