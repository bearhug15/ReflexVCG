# Reflex-AL → VC: спецификация генератора условий корректности (v2)

Версия 2 — переработана целиком, не патч поверх v1. Отличие от v1 не косметическое: инварианты теперь порождаются как формулы с ∀, ограниченным меткой границы шкалы (`toX`/`toXP`), а не как ссылка на непрозрачный предикат с ghost-полями внутри состояния. Следствие — **ни один оператор не нуждается в ghost-переменных вообще**: previously/next/once/during/on/cooldown/within/stable компилируются напрямую в кванторы по той же самой границе, по которой квантифицирует сам инвариант. assume/assert/variant остаются бескванторными — они проверяются в одной точке, а не «на каждой достигнутой границе».

## 1. Модель данных

### 1.1 Состояния и порядок

`State` — непрозрачный тип. `getVar(s,x)`, `setVar(s,x,v)` — как раньше. `<=` — линейный порядок на состояниях одной шкалы (историческая последовательность). Для каждой шкалы (программа, каждый for-цикл по отдельности) — своя пара «конструктор границы / предикат границы»:

```
toEnv  : State -> State      toEnvP  : State -> Bool      -- шкала program, одна на весь файл
toLoop : State -> State      toLoopP : State -> Bool       -- своя пара НА КАЖДЫЙ for, заново на каждое вхождение
```

Аксиома, общая для любой такой пары `(toX, toXP)`: `toXP(toX(s))` тождественно истинно, и `toXP` больше ни на чём не истинен, кроме как на образе `toX`. Отсюда — если `s1=toX(s0)` и `toXP(s1)`, то `toXP(s1)` не требует отдельного доказательства, только предъявления `s1` именно в такой форме.

### 1.2 IR — грамматика цели компиляции

```
IR ::= Bool(true|false)
     | GetVar(Ref, VarName)
     | And | Or | Not | Implies | Iff (IR,IR)
     | Cmp(op,IR,IR) | Arith(op,IR,IR)
     | ForallIdx(k,lo,hi,IR) | ExistsIdx(k,lo,hi,IR)      -- forall/exists языка выражений, по индексам массива
     | ForallSt(v, bound, IR) | ExistsSt(v, bound, IR)     -- НОВОЕ: квантор по State, bound — формула-ограничение на v
     | Choice(v, bound, IR)                                -- НОВОЕ: THE/SOME — для scope(prev)/scope(past)
```

`ForallSt`/`ExistsSt`/`Choice` — то, чем теперь напрямую выражаются previously/next/once/during/on/cooldown/within/stable/scope(prev)/scope(past). Никакого отдельного узла для ghost нет — в этой версии ghost не существует как понятие.

### 1.3 Ref — плейсхолдер вместо состояния

Ровно два, оба буквально текстовые метки, без структуры:

```
CUR    -- «эта точка»: то место, относительно которого annotation сформулирована
WIN    -- «начало окна»: живёт, только пока идёт компиляция под during/on; вне — не определено
```

Больше никакого `Offset(n)`: previously/next больше не сдвигают числовой индекс — они вводят СВЕЖУЮ связанную переменную квантором `ExistsSt` (см. §3.4). `CUR` и `WIN` — единственные свободные (несвязанные) `Ref` в любом `IR`, который порождает Проход 1; всё остальное в формуле, ссылающееся на состояние, — связанная переменная какого-то `ForallSt`/`ExistsSt`/`Choice`.

## 2. Архитектура: два прохода

**Проход 1.** `compile(content, ref, win) -> IR`, где на верхнем уровне `ref=CUR`, `win=`не определено. Результат — ОДНА формула, полностью готовая, с `CUR`/`WIN` как единственными свободными местами. Никакой сопутствующей структуры (ghost-декларации, как в v1) больше не возвращается — `compile` в этой версии одноместна по результату.

**Проход 2.** Подстановка. Для формулы `IR`, полученной на Проходе 1, и конкретных термов `term_cur`, `term_win` (второй — только если `IR` действительно содержит `WIN`):

```
bind(IR, term_cur, term_win) := IR[CUR := term_cur, WIN := term_win]
```

Буквальная, синтаксическая, capture-avoiding подстановка — не более того. Никакого анализа «есть ли предшественник», никакого разбора «гипотеза это или цель», никакого порядка вплетения (ghost-ов больше нет, вплетать нечего). Это и есть требуемое свойство: формула на выходе Прохода 1 уже полностью определяет свой смысл, Проход 2 её не достраивает, а только подставляет.

<a id="3"></a>
## 3. Проход 1 — компиляция содержимого аннотации

### 3.1 Точка входа и вспомогательный предикат

```
compile(expr, ref, win) -> IR
```

`ref` — текущая точка (изначально `CUR`, а дальше — либо `CUR`/`WIN`, либо связанная переменная, введённая previously/next/once/during/on ниже). `win` — текущее окно (изначально не определено; определено только внутри during/on, см. §3.6–3.7).

Один вспомогательный предикат, используется во всех операторах, читающих историю. Он не заводится Проходом 1 отдельно для каждого случая — это фиксированная часть языка целевых формул, определяемая один раз:

```
Adj(a,b) := a<b /\ toXP(a) /\ (\forall c. a<c /\ c<b ==> ~toXP(c))
            -- «a — ближайшая граница шкалы строго перед b»
            -- toXP здесь — предикат ТОЙ шкалы, на которой идёт компиляция (toEnvP или toLoopP,
            -- фиксируется один раз для всего содержимого одной annotation, не передаётся явно)
```

### 3.2 Булев/арифметический слой и атомарное чтение

Без изменений относительно v1, кроме отсутствия второго возвращаемого значения:

```
compile(A && B, ref, win)  = And(compile(A,ref,win), compile(B,ref,win))
compile(A || B, ref, win)  = Or(...)      -- аналогично для !, ==>, <==>, сравнений, арифметики
compile(forall(k in a..b: P(k)), ref, win) = ForallIdx(k,a,b, compile(P(k),ref,win))
compile(exists(k in a..b: P(k)), ref, win) = ExistsIdx(k,a,b, compile(P(k),ref,win))
compile(x, ref, win) = GetVar(ref, x)                          -- x: обычная переменная программы
```

### 3.3 previously(φ) / next(φ)

Симметрично, оба — просто новая связанная переменная через `Adj`, ghost не заводится вообще:

```
compile(previously(φ), ref, win) = ExistsSt(r', Adj(r',ref), compile(φ,r',win))
compile(next(φ),        ref, win) = ExistsSt(r', Adj(ref,r'), compile(φ,r',win))
```

`Adj(r',ref)` уже даёт «ложно, если такой границы нет» бесплатно, за счёт того, что это обычный `∃` над пустым при отсутствии свидетеля множеством — никакой отдельной ветки «нет состояния → false» писать не нужно, в отличие от v1. next теперь ничем принципиально не отличается от previously: обе стороны — просто вопрос о соседней по `<=` границе, не о том, что «ещё не построено» (это было проблемой только в модели с императивным построением ghost вперёд; здесь формула не строится, а пишется).

### 3.4 once(φ)

```
compile(once(φ), ref, win) = ExistsSt(r', r'<=ref /\ toXP(r'), compile(φ,r',win))
```

Дословно ∃j≤i.φ(j) из статьи, без всякого преобразования.

### 3.5 during(φ1,φ2,φm) — с зафиксированным ребиндингом φ2 и φm, с необязательным w0

```
compile(during(φ1,φ2,φm), ref, win) =
  ForallSt(r1,  w0(win)<=r1 /\ r1<=ref /\ toXP(r1) /\ compile(φ1,r1,win),
    Implies(
      ForallSt(r2, r1<r2 /\ r2<=ref /\ toXP(r2), Not(compile(φ2,r2,r1))),
      ForallSt(r3, r1<=r3 /\ r3<=ref /\ toXP(r3), compile(φm,r3,r1))
    )
  )

  где w0(win) := win, если win определён (during сам вложен в другой during/on),
                 иначе — первая граница текущей шкалы
```

φ1 компилируется с тем же `win`, что был снаружи (не переопределяется — φ1 не «внутри окна», он его определяет). φ2 и φm — оба на `WindowStart := r1` (это и есть правка, внесённая ранее в статью: φ2 ребиндится наравне с φm).

### 3.6 on(φ1,φ2) — одно правило на все случаи

```
compile(on(φ1,φ2), ref, win) =
  ForallSt(r1, w0(win)<=r1 /\ r1<=ref /\ toXP(r1) /\ compile(φ1,r1,win),
    compile(φ2, ref, r1))
```

φ2 компилируется на прежнем `ref` (не на `r1`!), но с `win:=r1`. Ветвления «φ2 зависит от WIN или нет», которое было в v1, здесь не требуется: если φ2 не ссылается на `WIN` внутри себя, `win:=r1` в неё просто не попадает ни в один `GetVar`/`Adj`/квантор — компиляция автоматически совпадает с упрощённой формой, без отдельного случая для этого в алгоритме.

### 3.7 timer(T) / within(T,φ) / stable(T,φ) — вложенные формы

Все три требуют, чтобы `win` был определён в точке вызова (иначе — ошибка компиляции, §6). Все три — прямая транскрипция определения, без переписывания родителя (в отличие от v1 — within(T,φ) в этой версии не трогает объемлющий during):

```
compile(timer(T),    ref, win) = Cmp(>=, Delta(win,ref), T)
compile(within(T,φ), ref, win) = Or(ExistsSt(r', win<=r' /\ r'<=ref /\ toXP(r'), compile(φ,r',win)),
                                     Cmp(<, Delta(win,ref), T))
compile(stable(T,φ), ref, win) = Implies(Cmp(<, Delta(win,ref), T), compile(φ,ref,win))
```

`Delta` — примитив базовой модели состояний (как `getVar`/`<=`), не конструируется этой спецификацией: число границ (или единиц времени) между двумя состояниями одной шкалы даётся извне.

### 3.8 cooldown(φ,T) — с необязательным w0

```
compile(cooldown(φ,T), ref, win) =
  ExistsSt(r', w0(win)<=r' /\ r'<=ref /\ toXP(r'), And(compile(φ,r',win), Cmp(<,Delta(r',ref),T)))
```

### 3.9 within(ψ,T,φ) / stable(ψ,T,φ) — самодостаточные формы

```
compile(within(ψ,T,φ), ref, win) = compile(during(ψ,φ,¬timer(T)), ref, win)
```
Desugar в during (§3.5) — поточечно точная редукция, подтверждена ранее; никакого нового правила не требуется, во исполнение уже установленного.

```
compile(stable(ψ,T,φ), ref, win) = compile(cooldown(ψ,T) ==> φ, ref, win)
```
Desugar в cooldown (§3.8) — не через during(ψ,timer(T),φ): та формула поточечно строже (требует φ на всём отрезке, не только в текущей точке), а stable спрашивает только «сейчас». В версии v1 это оправдывалось тем, что stable встречается только под invariant, и там их кумулятивный эффект совпадает; в этой версии оправдание проще — данная формула ЕСТЬ прямая, самостоятельно верная транскрипция смысла stable («если давно — недавно, то сейчас»), не нуждающаяся в обёртке invariant, чтобы быть корректной. Отсюда — снятие ограничения «только внутри invariant», см. §6.

### 3.10 scope(pre(e)) / scope(prev(e)) / scope(past(φ,e))

Термовые операторы. `scope(pre(e))` не двигает `ref` — «состояние перед этим оператором» покрывается порядком компиляции самого тела (см. §5.1), не требует ссылки на другую границу:

```
compile(scope(pre(e)), ref, win) = compile(e, ref, win)
```

`scope(prev(e))`/`scope(past(φ,e))` — термовые аналоги previously/once; там, где previously/once использовали `ExistsSt` (булев результат), термовый вариант использует `Choice` (реализуется как `SOME`/`Eps` целевой логики — если свидетель единственен, `Choice` даёт его; если свидетелей нет, даёт произвольное, ничем не связанное значение нужного типа — то есть именно ту неопределённость, которая нужна на входе шкалы):

```
compile(scope(prev(e)), ref, win) = compile(e, Choice(r', Adj(r',ref), Bool(true)), win)
compile(scope(past(φ,e)), ref, win) =
  compile(e, Choice(r', r'<=ref /\ toXP(r') /\ compile(φ,r',win) /\
                          (\forall r''. r'<r'' /\ r''<=ref /\ toXP(r'') ==> Not(compile(φ,r'',win))),
                     Bool(true)),
             win)
```

(Последнее условие под `Choice` — «и нет более позднего r'' с тем же свойством» — обеспечивает, что выбирается именно ближайшее, а не произвольное подходящее r'.)

### 3.11 in(ρ,ξ) / time(ρ)

Без изменений — не читают историю, не используют `win`:

```
compile(in(ρ,ξ), ref, win) = Cmp(==, GetVar(ref, state_of(ρ)), ξ)
compile(time(ρ), ref, win)  = GetVar(ref, time_in_state_of(ρ))
```

## 4. Проход 2 — подстановка

```
bind(IR, term_cur, term_win?) := IR[CUR := term_cur][WIN := term_win?]
```

Пример: `IR = Implies(GetVar(CUR,bad), Not(ExistsSt(r',Adj(r',CUR),GetVar(r',bad))))` (компиляция `bad ==> !previously(bad)`), связанное с `term_cur = σ'`: `Implies(GetVar(σ',bad), Not(ExistsSt(r',Adj(r',σ'),GetVar(r',bad))))` — буквальная замена текста `CUR` на `σ'`, ничего больше. Дальнейшее упрощение (например, что при `σ'=toLoop(...)` единственный `r'` с `Adj(r',σ')` — это состояние ДО применения `toLoop`, и `∃` можно сократить в прямую подстановку) — уже работа доказателя/симплификатора формул, не этой спецификации.

## 5. Сборка VC — единая схема сегментов

### 5.1 Общая форма

Программа (и каждый for-цикл внутри неё) — последовательность **сегментов**: максимальных участков прямого кода между двумя соседними границами, несущими инвариант (вход в цикл, выход из цикла, точка повторения program). Каждый сегмент даёт РОВНО один VC одной и той же формы:

```
Inv_before(paramsB, before) /\ toBeforeP(before) /\ [guard, если сегмент им открывается]
/\ <код сегмента как setVar-цепочка>
/\ after = toAfterMarker(<последнее состояние цепочки>)
==> Inv_after(paramsA, after)
```

`Inv_before`/`toBeforeP` цитируются как есть — гипотеза, не разворачивается (см. §5.2, определение `Inv_X` уже содержит квантор, повторно квантифицировать его в момент цитирования не нужно). Guard пишется только когда сегмент — это шаг УЖЕ ВОШЕДШЕГО цикла (шаг тела: `guard(before)`) или выход из цикла (`¬guard(before)`); вход в цикл и переход program→program его не имеют.

**Если код сегмента содержит вложенный for-цикл** — это НЕ отдельный случай схемы, а композиция трёх экземпляров той же схемы (вход-в-цикл / шаг / выход-из-цикла — свои три VC, порождаемые рекурсивно тем же правилом для этого вложенного цикла), плюс факт существования состояния-выхода, требуемый, чтобы продолжить setVar-цепочку сегмента ПОСЛЕ цикла:

```
Exits(toX, τ0, τ) := Inv_X(τ0,τ) /\ toXP(τ) /\ ¬guard_X(τ)

Lemma-Exit(τ0): \exists τ. Exits(toX,τ0,τ)
   -- доказывается ИЗ VC-входа и VC-шага этого цикла (индукция по достижимости)
      ПЛЮС отдельного аргумента терминации (variant, §5.4) — без variant это НЕ следует
      из одних только VC-входа/VC-шага, см. предыдущее обсуждение (`LoopReaches`).
```

Сегмент, код которого продолжается ПОСЛЕ вложенного цикла, берёт `τ` из `Lemma-Exit` (произвольный свидетель ∃, с уже доступными фактами `Inv_X(τ0,τ)`, `¬guard_X(τ)`) и продолжает свою собственную `setVar`-цепочку от него — не разворачивая цикл повторно.

### 5.2 invariant — определение `Inv_X`

Для каждой шкалы, несущей `invariant: P` (program целиком, либо конкретный for со своим `t0`):

```
Inv_program(s)     := \forall s1. s1<=s /\ toEnvP(s1)  ==> compile(P, s1, undef)
Inv_loop(t0, t)     := \forall t1. t0<=t1 /\ t1<=t /\ toLoopP(t1) ==> compile(P, t1, undef)
```

`toLoopP`/`toLoop` — свежая пара для КАЖДОГО вхождения `for` в исходном тексте (двух текстуально разных циклов эта пара не разделяют; один и тот же цикл, если он написан один раз, использует одну пару, даже если шкала program заставляет его перезапускаться много раз — параметризация через `t0` в `Inv_loop` и обеспечивает разделение разных запусков одного и того же текста цикла друг от друга).

### 5.3 assert / assume — вырожденный сегмент, без ∀

Содержимое `P` компилируется той же `compile(P, CUR, undef)`, но НЕ оборачивается в `Inv_X`/∀ — проверяется в одной точке:

```
assert, после помеченного оператора:
    Pre /\ <код от последней установленной точки до сюда> ==> bind(compile(P,CUR,undef), here, -)

assume, до помеченного оператора, на входе шкалы (нет предшественника):
    добавляется в Pre напрямую, VC не порождается

assume, до помеченного оператора, не на входе:
    Pre /\ <код...> ==> bind(compile(P,CUR,undef), here, -)
    (после доказательства — тоже добавляется в Pre, как и assert)
```

Если `P` внутри assert/assume использует once/during/cooldown/on — эти операторы всё равно порождают собственные `ExistsSt`/`ForallSt` (см. §3) — «бескванторность» здесь означает отсутствие ВНЕШНЕГО, привязанного к самой annotation ∀ по границам шкалы, а не отсутствие кванторов вообще; квантор, принадлежащий конкретному оператору внутри `P`, никуда не девается.

### 5.4 variant — два обязательства, оба без ∀

```
//[variant: V]  на for-цикле с телом τ→τ':

VC-var-1: Inv_loop(t0,τ) /\ toLoopP(τ) /\ guard(τ) ==> bind(compile(V,CUR,undef),τ,-) >= 0
VC-var-2: Inv_loop(t0,τ) /\ toLoopP(τ) /\ guard(τ)
          /\ <тело: τ1=..., τ'=toLoop(τ1)>
          ==> bind(compile(V,CUR,undef),τ,-) > bind(compile(V,CUR,undef),τ',-)
```

Именно эти два, вместе с VC-входа/VC-шага того же цикла, и дают `Lemma-Exit` из §5.1 — полной индукцией по значению `V`, а не как отдельное, никак не обоснованное допущение.

### 5.5 define — без изменений

Чистая макроподстановка на Проходе 1, до применения §3.1–3.11 к месту использования; не порождает VC, не использует `CUR`/`WIN` как что-то, требующее связывания отдельно от места, где `name` фактически встретился.

## 6. Проверки корректности

Проход 1 обязан завершиться ошибкой, если:

- `timer(T)` / `within(T,φ)` / `stable(T,φ)` встречены при неопределённом `win` — то есть вне φ2/φm объемлющего `during`, вне φ2 объемлющего `on`.
- `next(φ)` — bare (`next(true)`/`next(false)`, без всякой охраны) как содержимое `invariant`: `Inv_X`, раскрытый на последней границе шкалы (где `guard` уже ложен), для `next(true)` требует существования границы ПОСЛЕ последней — противоречие с тем, что она последняя. Формально это не отдельная синтаксическая проверка (в отличие от v1, где это было следствием того, что ghost не может знать будущее) — теперь это просто одна из VC (шаг цикла на последней итерации, точнее сама VC-выхода, §5.1) оказывается недоказуемой; тем не менее ЭТУ конкретную форму стоит ловить статически, как заведомо тупиковую, не дожидаясь провала у доказателя.
- Снято относительно v1: `within(ψ,T,φ)`/`stable(ψ,T,φ)` больше не ограничены содержимым `invariant` — обе компилируются (§3.9) в самостоятельно корректные формулы независимо от контекста.

## 7. Сквозной пример

```
//[invariant: c>0]
program {
  a=1; b=1;
  //[invariant: b>0]
  for (; a<10; a++) { b += 1; }
  c += b;
}
```

**compile:** содержимое обоих инвариантов не использует темпоральных операторов, поэтому `compile` тривиальна: `compile(c>0, ref, win) = Cmp(>, GetVar(ref,c), 0)`, `compile(b>0, ref, win) = Cmp(>, GetVar(ref,b), 0)`.

**§5.2:**
```
Inv_prog(s)     := \forall s1. s1<=s /\ toEnvP(s1) ==> (getVar s1 c) > 0
Inv_loop(t0,t)  := \forall t1. t0<=t1 /\ t1<=t /\ toLoopP(t1) ==> (getVar t1 b) > 0
```

**§5.1, три сегмента:**

```
VC1 (вход в цикл):
    Inv_prog(s) /\ toEnvP(s)
    /\ sa = setVar s a 1 /\ sb = setVar sa b 1 /\ t0 = toLoop sb
    ==> Inv_loop(t0, t0)

VC2 (шаг цикла):
    Inv_loop(t0,t) /\ toLoopP(t) /\ (getVar t a) < 10
    /\ t1 = setVar t b ((getVar t b)+1) /\ t2 = setVar t1 a ((getVar t1 a)+1) /\ t' = toLoop t2
    ==> Inv_loop(t0, t')

VC3 (выход из цикла):
    Inv_loop(t0,t) /\ toLoopP(t) /\ ~((getVar t a) < 10)
    /\ sc = setVar t c ((getVar t c) + (getVar t b)) /\ s1 = toEnv sc
    ==> Inv_prog(s1)
```

Совпадает буквально с тем, что было выведено вручную. Отдельно — `VC-prog-entry` (не входила в предыдущий обмен как отдельный пункт, но того же §5.1: программа сама начинается сегментом «от `s_init` до первой своей границы», без предшествующего `Inv_before`):

```
VC0 (вход в программу):
    Pre(s_init) /\ s0 = toEnv s_init ==> Inv_prog(s0)
```

**Пример с оператором, недоступным без v2-машины** — если бы `invariant` цикла был `previously(b>5) ==> b>10` вместо `b>0`:

```
compile(previously(b>5) ==> b>10, ref, win) =
  Implies(
    ExistsSt(r', Adj(r',ref), Cmp(>,GetVar(r',b),5)),
    Cmp(>,GetVar(ref,b),10)
  )
```

Готовая формула, без ghost. В VC2 (шаг цикла) при связывании `ref:=t'`: `Adj(r',t')` — единственный `r'`, ему удовлетворяющий, это уже имеющееся `t` из антецедента VC2 (поскольку `t'=toLoop(t2)`, а `Adj` ищет ближайшую границу СТРОГО перед `t'`, и по построению шкалы это `t`) — упрощение `∃r'.Adj(r',t')∧P(r')` до `P(t)` доказатель делает сам, из аксиом `toLoop`/`<=`, не из указаний этой спецификации.

## 8. Сводная таблица по операторам

| Оператор | Компиляция (кратко) |
|---|---|
| previously(φ) | `∃r'. Adj(r',ref) ∧ φ@r'` |
| next(φ) | `∃r'. Adj(ref,r') ∧ φ@r'` |
| once(φ) | `∃r'≤ref, toXP(r'). φ@r'` |
| during(φ1,φ2,φm) | `∀r1∈[w0,ref], φ1@r1. (∀r2∈(r1,ref].¬φ2@r2,win:=r1) ⟹ (∀r3∈[r1,ref].φm@r3,win:=r1)` |
| on(φ1,φ2) | `∀r1∈[w0,ref], φ1@r1. φ2@ref,win:=r1` |
| timer(T) | `Δ(win,ref)≥T` (win обязателен) |
| within(T,φ) | `(∃r'∈[win,ref].φ@r') ∨ Δ(win,ref)<T` (win обязателен) |
| stable(T,φ) | `Δ(win,ref)<T ⟹ φ@ref` (win обязателен) |
| cooldown(φ,T) | `∃r'∈[w0,ref].φ@r' ∧ Δ(r',ref)<T` |
| within(ψ,T,φ) | desugar → during(ψ,φ,¬timer(T)) |
| stable(ψ,T,φ) | desugar → cooldown(ψ,T)⟹φ |
| scope(pre(e)) | `e@ref` (без сдвига) |
| scope(prev(e)) | `e@(CHOICE r'. Adj(r',ref))` |
| scope(past(φ,e)) | `e@(CHOICE r'. r'≤ref∧toXP(r')∧φ@r'∧ближайшее)` |
| in(ρ,ξ), time(ρ) | обычное чтение поля состояния `ref` |

Ни одна строка не заводит ghost-поле; «win обязателен» — единственная оставшаяся статическая проверка (§6).
